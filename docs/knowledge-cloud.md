# Exploring the knowledge cloud

The cloud reads active canonical knowledge. Repository, package/directory and file
points are explicitly labelled aggregates; symbol points identify actual captured
entities. Expand an aggregate, then page through its members. Counts distinguish
the selected scope from the visible page. A page contains at most 256 points;
relationship lines connect only visible endpoints and carry canonical claim
and source evidence. Hidden endpoints and truncated relationships are disclosed.

The hierarchy groups captured module manifests where available and otherwise
labels directory groups explicitly. A directory is not a claim that the code
forms a language package. Generation provenance and coverage are available for
every page. Captured knowledge can be exact while language or repository coverage
is incomplete; an empty group does not establish absence outside captured scope.

Drag the view to rotate in three dimensions, Shift-drag to pan, and scroll to
zoom. Keyboard users can focus the view and use arrows, Shift-arrows, +/− and
Home, or use the accessible evidence member list. Expand controls change the
semantic level; camera zoom changes perspective within that level. Geometry is
a deterministic layout and does not imply relationship strength or causality.
The semantic colour legend is independent of the instance's branding colour.

Selecting a symbol opens canonical source evidence. Selecting a relationship
opens its own cited evidence. Source actions are validated against the active
capture and current local source before they can run. Stale, changed, unsafe or
unsupported destinations are disabled with a reason. Remote destinations refer
to the captured commit; a working-tree capture cannot be represented faithfully
by an unchanged remote commit link.

Spotlight selections reveal their containing file page. Pink identifies returned
entities and claims present on that page; other points are subdued. This is an
evidence highlight, not an invented execution or causal path. Bounded results
may require additional pages or a refined query.

Build activity is labelled as staging and is never queryable evidence. The active
cloud changes only after a real generation promotion. Comparable page changes
animate entering and leaving members. Replacing a paginated or focused page is
labelled as a page replacement, not as a complete knowledge delta. Reduced motion
keeps the same information with immediate position changes. Graphics context
loss leaves the evidence list usable and restores the view from the current page.

Rendering happens on interaction and observed changes, not continuously at idle.
Large scopes use bounded paging. Native performance measurements report the
hardware, visible detail and actual rendering work; they do not claim that every
repository size meets a universal frame-rate target.
