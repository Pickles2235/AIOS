## Decisions

- Inspect and follow the existing Go/SQLite/mirror/MCP/browser contracts; do not
  implement the seven product tasks in the harness change. Preserve the module path.
- Use a standard-library Python queue/launcher plus Make targets and a small
  POSIX dependency setup script, reusing the existing test/build/acceptance tools.
- Keep task completion status explicit and verify predecessor commit ancestry against
  fetched origin/main and HEAD. Order the seven tasks sequentially for isolated
  reviews and integrated first-run acceptance.
- Use one `codex exec --sandbox workspace-write` invocation. The installed CLI
  help has no --full-auto option. Inherit model/auth; never run a real model in
  regression tests. Lock the Git common directory across linked worktrees.
- Preserve failed-run branches and logs. Fail closed on stale locks; document
  recovery rather than automatically clearing locks or retrying model calls.
- Require a JDK in setup because current full Go tests require Java compiler
  coverage, despite compiler helpers being optional during product ingestion.
- Use dedicated Linux/macOS harness CI; existing native CI also discovers the
  Python regression tests. Remote CI results have not been observed locally.
